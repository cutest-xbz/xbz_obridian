这行：

```text
/dev/sda3: clean, ... files, ... blocks
```

不是报错，表示文件系统检查正常。真正的问题很可能是：**之前根分区已经 100% 占满；你在 VMware 中扩大了虚拟硬盘，但 Ubuntu 的 `/dev/sda3` 分区和文件系统还没有同步扩大**，所以图形桌面启动不了。

## 先进入命令行释放空间

在这个黑屏界面按：

```text
Ctrl + Alt + F3
```

出现登录界面后，输入 Ubuntu 用户名和密码。密码输入时不会显示字符。

登录后执行：

```bash
df -h /
lsblk -f
```

先紧急释放一些空间：

```bash
sudo apt clean
sudo rm -f /var/crash/*
sudo journalctl --vacuum-size=100M

rm -rf ~/.cache/thumbnails/*
rm -rf ~/PX4-Autopilot/log/*
```

如果仍然接近 100%，删除 PX4 编译缓存：

```bash
rm -rf ~/PX4-Autopilot/build
```

这不会删除 PX4 源码，但下次仿真需要重新编译。

检查空间：

```bash
df -h /
```

然后重启：

```bash
sudo reboot
```

## 把新增硬盘空间扩展到 `/dev/sda3`

重新能进入系统后，先确认磁盘情况：

```bash
lsblk
```

假设看到类似：

```text
sda      80G
├─sda1
├─sda2
└─sda3   39G  /
```

说明 VMware 虚拟硬盘已经是 80 GB，但根分区仍只有 39 GB。

先安装扩容工具：

```bash
sudo apt update
sudo apt install cloud-guest-utils -y
```

扩展第 3 个分区：

```bash
sudo growpart /dev/sda 3
```

再扩展 ext4 文件系统：

```bash
sudo resize2fs /dev/sda3
```

检查结果：

```bash
df -h /
lsblk
```

根分区应从约 39 GB 增加到新的容量。

## 按 `Ctrl + Alt + F3` 没反应

重启虚拟机，启动时反复按 `Esc` 进入 GRUB，然后选择：

```text
Advanced options for Ubuntu
→ 带 recovery mode 的内核
→ root
```

进入 root 命令行后先执行：

```bash
mount -o remount,rw /
```

再执行前面的清理命令。

**暂时不要反复强制关机。** 先执行 `lsblk -f` 和 `df -h /`，确认 `/dev/sda` 与 `/dev/sda3` 的实际容量后再扩容。
