# 基于 FPGA 的自动音乐播放与动态视觉交互系统设计

## Codex 辅助开发实施方案

### 一、项目目标

本项目拟基于 FPGA 平台实现一个“自动音乐播放 + 动态视觉交互”的综合数字系统。系统以 50MHz 主时钟为全局时钟源，通过 Verilog HDL 实现乐谱读取、节拍控制、音频方波生成、PWM 呼吸灯和流水灯视觉效果。

目标功能包括：

1. 自动从 ROM 中读取乐谱数据；
    
2. 根据音高编码产生不同频率的蜂鸣器方波；
    
3. 根据音长编码控制每个音符的持续时间；
    
4. 使用 PWM 控制多个 LED 的亮度变化；
    
5. 实现流水式、呼吸式 LED 动态视觉效果；
    
6. 在 Quartus Prime 中完成综合、适配、引脚约束、编译与下板验证；
    
7. 形成完整的 Verilog 源码、仿真文件、工程脚本和答辩说明材料。

### 四、系统模块划分

#### 1. 顶层模块 `top.v`

顶层模块负责连接所有子模块。

输入信号：

```verilog
input wire clk_50m;
input wire rst_n;
```

输出信号：

```verilog
output wire buzzer;
output wire [3:0] led;
```

顶层连接关系：

```text
clk_50m / rst_n
      │
      ├── beat_gen：生成节拍使能信号
      │
      ├── music_ctrl：控制 ROM 地址、读取音符和音长
      │
      ├── note_rom：存储乐谱数据
      │
      ├── tone_gen：根据音高生成蜂鸣器方波
      │
      └── breath_led / flow_led：生成动态 LED 效果
```

---

#### 2. 节拍发生模块 `beat_gen.v`

功能：

1. 基于 50MHz 时钟生成慢速节拍使能信号；
    
2. 为音乐播放状态机提供节拍基准；
    
3. 为 LED 呼吸变化提供较慢的更新节奏。
    

输出建议：

```verilog
output reg tick_1ms;
output reg tick_10ms;
output reg tick_beat;
```

设计原则：

不要在 FPGA 内部随意产生新的慢时钟，而应使用同步计数器产生 `clock enable` 信号，避免多时钟域带来的亚稳态和毛刺问题。

---

#### 3. 乐谱控制模块 `music_ctrl.v`

功能：

1. 控制 ROM 地址递增；
    
2. 读取当前音符数据；
    
3. 解析音高和音长；
    
4. 使用有限状态机实现自动播放流程。
    

推荐 FSM：

```text
IDLE -> READ -> PLAY -> WAIT -> NEXT -> READ
```

状态说明：

- `IDLE`：系统复位或等待开始；
    
- `READ`：读取 ROM 中当前音符；
    
- `PLAY`：输出当前音符编码；
    
- `WAIT`：根据音长等待指定节拍数；
    
- `NEXT`：ROM 地址加一，读取下一个音符。
    

乐谱数据格式建议：

```text
[7:4] 音高编码
[3:0] 音长编码
```

例如：

```text
8'h11：低音 Do，1 拍
8'h22：Re，2 拍
8'h34：Mi，4 拍
8'h00：休止符
8'hFF：乐曲结束标志
```

---

#### 4. ROM 乐谱模块 `note_rom.v`

实现方式有两种：

方案 A：使用 Quartus IP Catalog 生成 LPM_ROM。

优点：

- 更贴近 Quartus 工程规范；
    
- 可以直接使用 `.mif` 初始化；
    
- 方便展示 Block RAM 资源占用。
    

方案 B：使用 Verilog `case` 或 `$readmemh` 实现。

优点：

- 更容易由 Codex 自动生成；
    
- 更方便仿真；
    
- 便于初期调试。
    

建议开发流程：

先使用 Verilog 行为级 ROM 完成仿真，确认音乐逻辑正确后，再替换为 Quartus LPM_ROM IP 核。

---

#### 5. 音频发生模块 `tone_gen.v`

功能：

1. 接收音高编码；
    
2. 查询对应分频计数阈值；
    
3. 使用可变模值计数器产生方波；
    
4. 输出到无源蜂鸣器。
    

计算公式：

```text
计数阈值 = 50_000_000 / (目标频率 × 2)
```

示例频率表：

|音符|频率|计数阈值近似值|
|---|--:|--:|
|Do|261.6 Hz|95566|
|Re|293.7 Hz|85178|
|Mi|329.6 Hz|75873|
|Fa|349.2 Hz|71592|
|Sol|392.0 Hz|63776|
|La|440.0 Hz|56818|
|Si|493.9 Hz|50617|

休止符时，蜂鸣器输出固定低电平。

---

#### 6. PWM 呼吸灯模块 `pwm_core.v`

功能：

1. 使用 PWM 计数器产生亮度调制；
    
2. 通过比较 `pwm_cnt < duty` 输出 PWM 波；
    
3. 支持多路 LED 独立占空比输入。
    

核心逻辑：

```verilog
assign pwm_out = (pwm_cnt < duty) ? 1'b1 : 1'b0;
```

PWM 频率建议大于 100Hz，避免肉眼可见闪烁。

---

#### 7. 流水呼吸灯模块 `breath_led.v / flow_led.v`

功能：

1. 产生递增、递减的三角波占空比；
    
2. 形成单灯呼吸效果；
    
3. 通过移位寄存器或亮度数组循环移动，实现流水效果。
    

推荐亮度梯度：

```text
LED0：100%
LED1：70%
LED2：40%
LED3：10%
```

每隔一段时间循环移位：

```text
100%, 70%, 40%, 10%
10%, 100%, 70%, 40%
40%, 10%, 100%, 70%
70%, 40%, 10%, 100%
```

这样可以同时体现“呼吸”和“流水”的视觉交互效果。

### 九、项目风险与解决方案

#### 风险 1：Codex 生成的 Verilog 不可综合

解决方案：

- 明确要求“可综合 Verilog”；
    
- 避免使用 `initial` 作为硬件逻辑；
    
- 避免使用延时语句 `#10`；
    
- Testbench 中可以使用不可综合语句，但 RTL 中不能使用。
    

#### 风险 2：引脚约束错误

解决方案：

- 引脚必须查阅正点原子开发板原理图；
    
- Codex 只生成 `.qsf` 模板；
    
- 最终 PIN 编号人工确认。
    

#### 风险 3：蜂鸣器无声

可能原因：

- 蜂鸣器类型不匹配；
    
- 方波频率过高或过低；
    
- 引脚分配错误；
    
- 输出极性错误；
    
- 蜂鸣器需要三极管驱动。
    

解决方案：

- 先固定输出 1kHz 方波测试蜂鸣器；
    
- 再接入音乐模块；
    
- 用示波器或逻辑分析仪观察输出波形。
    

#### 风险 4：LED 亮度变化不明显

可能原因：

- PWM 频率不合适；
    
- 占空比分辨率过低；
    
- LED 低电平有效；
    
- 呼吸变化速度太快或太慢。
    

解决方案：

- 先单独测试 PWM；
    
- 确认 LED 是高电平点亮还是低电平点亮；
    
- 调整 PWM 周期和 duty 更新速度。
    

#### 风险 5：ROM IP 使用复杂

解决方案：

- 初期使用 Verilog 行为级 ROM；
    
- 功能稳定后再替换为 Quartus LPM_ROM；
    
- 保留 `.mif` 文件用于工程展示。
